# Как получить APK (Android) для PlayZone CRM — через GitHub

Приложение — это «обёртка» (TWA) вокруг вашего работающего сайта: телефон
открывает ту же CRM, что и браузер, но на весь экран, с вашей иконкой, без
адресной строки. Оффлайн-режим, сирена и очередь операций работают так же,
потому что внутри — Chrome.

Весь путь: **развернуть сайт по HTTPS → залить код на GitHub → запустить
готовый workflow → скачать APK**. На компьютер ничего устанавливать не нужно —
сборка идёт на серверах GitHub бесплатно.

---

## Шаг 0. Что уже готово в проекте

* `android/` — готовый Android-проект (TWA-обёртка): манифест, иконки,
  подпись, splash-экран. Собирается командой Gradle без единого вопроса.
* `.github/workflows/build-apk.yml` — workflow сборки: сам подставляет ваш
  адрес, название и packageId, создаёт/подписывает ключом, выпускает
  `PlayZone-CRM.apk` + `assetlinks.json` + ключ подписи.
* `public/manifest.json`, иконки, service worker — на месте (PWA готова).

## Шаг 1. Развернуть CRM по HTTPS (обязательно)

APK открывает ваш сайт, поэтому адрес должен работать по `https://...`.

Выберите один из трёх вариантов:

| Вариант | Стоимость | Что нужно |
|---------|-----------|-----------|
| **C: Neon + Vercel** — рекомендуется при бюджете 0 ₸ | **0 ₸ навсегда** | только браузер, деплой по push как на Netlify |
| A: VPS + автодеплой | ~3–5 $/мес | браузерный терминал VPS, полный контроль |
| B: Cloudflare Tunnel | 0 ₸ (+ домен для постоянного адреса) | компьютер клуба должен быть включён |

### Вариант C: полностью бесплатно — Neon (база) + Vercel (хостинг)

На ваш компьютер не ставится ничего — всё делается в браузере. CRM и база
живут в облаке, работают 24/7 без включённого компьютера в клубе.

**C-1. Бесплатная база Neon (2 минуты)**

1. Откройте `neon.tech` → **Sign up with GitHub** → Create project:
   имя `playzone`, регион ближайший к Казахстану (например, Frankfurt).
2. На странице проекта найдите **Connection string** и скопируйте
   **обе** строки: обычную и **Pooled** (переключатель на той же панели).
   Вид: `postgresql://...neon.tech/neondb?sslmode=require`.
3. Бесплатный тариф не требует карты и не «засыпает» — база всегда готова.

**C-2. Деплой на Vercel (5 минут)**

1. Откройте `vercel.com` → **Continue with GitHub** → **Add New → Project**
   → Import ваш репозиторий `playzone-crm`.
2. Перед нажатием Deploy раскройте **Environment Variables** и добавьте:

   | Имя | Значение |
   |-----|----------|
   | `DATABASE_URL` | Pooled-строка из Neon |
   | `TZ` | `Asia/Almaty` |

3. **Deploy** → через 2–3 минуты сайт живёт на
   `https://имя-проекта.vercel.app` — откройте с телефона, проверьте вход.
4. С этого момента любой `git push` в `main` обновляет сайт сам — как на
   Netlify, только без ограничений по числу сборок.

**C-3. Создать таблицы в базе (1 клик)**

1. В Neon скопируйте **обычную** (не Pooled) строку → в GitHub репозитории:
   **Settings → Secrets → Actions → New repository secret** → имя
   `DATABASE_URL_DIRECT`, значение — эта строка.
2. Вкладка **Actions** → «Init Neon database» → Run workflow → seed оставить
   включённым → Run. Workflow создаст таблицы и демо-данные
   (admin/admin, устройства, пакеты) — на сервер ничего не ставится.
3. Откройте сайт → войдите admin/admin → смените пароли в Настройках.

> У вас уже есть данные в старой базе? Скажите — перенесу их скриптом
> `scripts/migrate-sqlite-to-postgres.ts` (сеансы, касса, клиенты, турниры).

**C-4. APK** — стандартно: Шаг 3 (секреты подписи) → Шаг 4 (Run workflow,
в поле `pwa_url` укажите `https://имя-проекта.vercel.app`).

> Лимиты бесплатного тарифа (с запасом): 1 млн вызовов функций/мес —
> опрос экрана в CRM уже настроен под это (10 с, пауза при свёрнутом окне);
> 100 деплоев/день — вам хватит. Hobby-тариф Vercel формально для
> некоммерческих проектов: когда клуб вырастет — переезд на Вариант A
> занимает ~30 минут, база остаётся той же (Neon).

### Вариант A: VPS + автодеплой — «как Netlify, push → само обновляется»

На ваш компьютер не ставится ничего: весь сетап — в браузерном терминале VPS.

**A-1. VPS и домен**

1. Купите VPS: Ubuntu 24.04, 1–2 GB RAM, ~3–5 $/мес (PS.kz, Hostinger,
   Timeweb). Бесплатный навсегда вариант — Oracle Cloud «Always Free»
   (регистрация сложнее). В панели провайдера откройте **браузерный
   терминал** сервера (Console / Web console) под пользователем `root`.
2. Купите домен (или бесплатный `xxx.duckdns.org`) и добавьте **A-запись**,
   указывающую на IP сервера (у duckdns — просто впишите IP). Подождите
   5–15 минут.

**A-2. Первый запуск CRM (одна команда в терминале VPS)**

База — бесплатный Neon (как в Варианте C, шаг C-1): создайте проект,
скопируйте обычную строку подключения и подставьте в команду:

```bash
apt update && apt install -y git
git clone https://github.com/ВАШ_ЛОГИН/playzone-crm.git /opt/playzone
bash /opt/playzone/scripts/server-setup.sh crm.ваш-домен.kz 'postgresql://...neon.tech/neondb?sslmode=require'
```

Скрипт сам: добавит swap, поставит Bun, создаст `.env` (адрес базы +
таймзона), создаст таблицы, соберёт CRM, включит автозапуск после
перезагрузки (systemd), настроит Caddy с HTTPS-сертификатом.
Демо-данные: `cd /opt/playzone && DATABASE_URL=$(grep DATABASE_URL .env | cut -d= -f2-) bunx tsx scripts/seed.ts`.
Проверка: `https://crm.ваш-домен.kz` открывается с телефона.

**A-3. Автодеплой: push → сайт обновляется сам (как на Netlify)**

В терминале VPS создайте два ключа (для выгрузки кода и для подключения
GitHub):

```bash
# ключ, которым GitHub заходит на сервер (копируем содержимое приватного):
ssh-keygen -t ed25519 -f /root/.ssh/gh_deploy -N ""
cat /root/.ssh/gh_deploy.pub >> /root/.ssh/authorized_keys
cat /root/.ssh/gh_deploy            # ЭТО скопировать в секрет SSH_PRIVATE_KEY

# ключ только на чтение репозитория (git pull на сервере):
ssh-keygen -t ed25519 -f /root/.ssh/github_ro -N ""
cat /root/.ssh/github_ro.pub        # ЭТО вставить на GitHub → Deploy keys (read-only)

git -C /opt/playzone remote set-url origin git@github.com:ВАШ_ЛОГИН/playzone-crm.git
git -C /opt/playzone config core.sshCommand "ssh -i /root/.ssh/github_ro -o IdentitiesOnly=yes"
```

В GitHub: **Settings → Secrets and variables → Actions → New repository
secret** (три секрета для деплоя):

| Имя секрета        | Значение                                  |
|--------------------|-------------------------------------------|
| `SSH_HOST`         | IP сервера                                 |
| `SSH_USER`         | `root`                                     |
| `SSH_PRIVATE_KEY`  | содержимое `/root/.ssh/gh_deploy` (целиком) |

Готово: workflow **«Deploy to VPS»** срабатывает на каждый `git push` в
`main` — сервер сам делает pull → сборку → перезагрузку CRM (прогресс виден
во вкладке Actions). Изменения в CRM попадают на сайт за 2–3 минуты после
push.

> Почему не Netlify напрямую: CRM хранит данные в базе и работает как
> постоянный Node-сервер — на «чистом» Netlify файловой базы нет, а опрос
> экрана каждые 5–10 секунд сжёг бы бесплатные лимиты функций за считанные
> дни. Поэтому для нулевого бюджета используйте связку Neon + Vercel
> (Вариант C) — она собрана и протестирована под лимиты бесплатных тарифов.

### Вариант B: без VPS — Cloudflare Tunnel (бесплатно)

CRM работает на вашем компьютере/мини-ПК (он должен быть включён во время
работы клуба; спящий режим отключить). Кратко:

1. Установите Node.js 20+ (или Bun) и cloudflared
   (github.com/cloudflare/cloudflared/releases → cloudflared-windows-amd64.exe).
2. Создайте бесплатную базу Neon (шаг C-1) и запустите CRM с её адресом
   (на Windows — в Git Bash из комплекта Git for Windows):
   ```bash
   bun install
   DATABASE_URL='postgresql://...neon.tech/neondb?sslmode=require' bunx prisma db push
   DATABASE_URL='postgresql://...neon.tech/neondb?sslmode=require' bunx tsx scripts/seed.ts
   DATABASE_URL='postgresql://...neon.tech/neondb?sslmode=require' bun run build
   DATABASE_URL='postgresql://...neon.tech/neondb?sslmode=require' bun run start
   ```
3. Быстрый тест без аккаунта (адрес меняется при каждом запуске — для APK
   НЕ годится): `cloudflared tunnel --url http://localhost:3000` → откройте
   выданный `https://…trycloudflare.com`.
4. Постоянный адрес: купите дешёвый домен → добавьте в Cloudflare
   (dash.cloudflare.com → Add site → Free) → смените NS у регистратора →
   `cloudflared tunnel login` → `cloudflared tunnel create playzone` →
   `cloudflared tunnel route dns playzone crm.ваш-домен` → в
   `~/.cloudflared/config.yml` пропишите туннель и
   `service: http://localhost:3000` → `cloudflared tunnel run playzone`.
5. Автозапуск: Windows — `start.bat` (CRM) и `tunnel.bat` (туннель) в папку
   автозагрузки (Win+R → shell:startup); Linux — `pm2` для CRM и
   `sudo cloudflared service install` для туннеля.
6. Бэкап: данные живут в Neon (бэкапы делает сама платформа в панели
   проекта).

> ⚠️ Проверка: откройте адрес с телефона в Chrome — CRM должна открываться
> и работать (вход admin/admin и т.д.).

## Шаг 2. Залить код на GitHub

```bash
git init                     # если ещё не репозиторий
git add .
git commit -m "PlayZone CRM + APK build"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/playzone-crm.git
git push -u origin main
```

(`db/custom.db` с реальными данными пушить не нужно — база создаётся
`bun run db:push` на сервере; он уже в `.gitignore`.)

## Шаг 3. Секреты подписи (один раз)

В репозитории: **Settings → Secrets and variables → Actions → New repository
secret**:

| Имя секрета                   | Значение                                            |
|-------------------------------|-----------------------------------------------------|
| `ANDROID_KEYSTORE_PASSWORD`   | придумайте пароль 8+ символов и сохраните           |
| `ANDROID_KEY_ALIAS_PASSWORD`  | тот же пароль                                       |

Без них сборка остановится с понятной ошибкой — это защита от того, чтобы
каждая сборка подписывалась новым ключом.

## Шаг 4. Запустить сборку APK

1. Вкладка **Actions** репозитория → слева **«Build Android APK»**.
2. **Run workflow** → заполните поля:
   * `pwa_url` — ваш HTTPS-адрес, например `https://crm.ваш-домен.kz`;
   * `app_name` — название на телефоне (по умолчанию «PlayZone CRM»);
   * `app_id` — не меняйте (`kz.playzone.crm`), менять только если понимаете зачем;
   * `version_code` — оставьте пустым (номер версии растёт сам с каждым запуском).
3. **Run workflow** → ждите ~5 минут (зелёная галочка).
4. Откройте завершившийся запуск → внизу **Artifacts** → скачайте
   **PlayZone-APK**. Внутри три файла:
   * `PlayZone-CRM.apk` — **тот самый файл для Android**;
   * `assetlinks.json` — положите на сервер (шаг 5);
   * `android.keystore` — ключ подписи. **Сохраните навсегда** (облако,
     флешка): все будущие версии должны подписываться им же.

## Шаг 5. Убрать адресную строку (assetlinks.json)

Из артефакта возьмите `assetlinks.json` и положите на сервер в проект:

```bash
mkdir -p public/.well-known
# скопируйте файл в public/.well-known/assetlinks.json
git add public/.well-known/assetlinks.json
git commit -m "assetlinks"
git push
# на сервере: git pull && bun run build && pm2 restart playzone
```

Проверка: `https://ваш-адрес/.well-known/assetlinks.json` должен открыть JSON.
Теперь при запуске APK не будет адресной строки (может понадобиться
перезапустить приложение 1–2 раза — Chrome проверяет связь с задержкой).

## Шаг 6. Установить и раздать сотрудникам (Android)

* Отправьте `PlayZone-CRM.apk` в Telegram/WhatsApp — на телефоне открывают
  и устанавливают (Android попросит разрешить установку из этого источника).
* Требование: Android 7.0+ (2016+), любой, где есть Chrome (он предустановлен).
* Для громких уведомлений о конце времени: **настройки Android → Приложения →
  PlayZone CRM → Уведомления: разрешить, звук, вибрация**; отключите
  экономию батареи для приложения (иначе Android «усыпляет» сирену в фоне).

## А если у сотрудника iPhone?

APK ставится только на Android — это нормально. CRM по своей природе сайт,
и на iPhone она открывается по **той же самой ссылке** в Safari: тот же
вход, те же данные (всё живёт на сервере, а не в телефоне). Ничего
покупать, собирать и устанавливать для iPhone не нужно.

Чтобы на iPhone это выглядело как обычное приложение (иконка на экране,
во весь экран, без адресной строки) — 30 секунд один раз:

1. Откройте ссылку CRM в **Safari** (именно Safari: Chrome на iPhone
   не умеет добавлять сайты на экран «Домой»).
2. Кнопка **«Поделиться»** (квадрат со стрелкой вверх) → листайте вниз →
   **«На экран „Домой“»** → «Добавить».
3. На экране появится иконка **PlayZone CRM**. Запуск с неё открывает CRM
   на весь экран — внешне не отличить от приложения из App Store.

Всё работает так же, как на Android: таймеры, оплата, отчёты,
оффлайн-режим. Два честных нюанса iOS:

* **Фоновых push на iPhone у сайта не бывает.** На iOS так устроена
  система: громкая сирена надёжно срабатывает, пока CRM открыта на экране.
  Если для смены важно оповещение в фоне — на iPhone сотруднику лучше
  держать CRM открытой на стойке (или использовать Android + APK, где
  сирена работает и в фоне).
* Если Safari долго не открывали (7+ дней), iOS может очистить локальный
  кэш — данные не пропадают (они на сервере), просто потребуется заново
  ввести пароль.

Настоящее приложение в App Store (с пушами через Apple) — это аккаунт
разработчика Apple за 99 $/год, Mac для сборки и проверка приложения
модераторами Apple. Для клуба это избыточно: иконка на «Домой» решает
ту же задачу бесплатно и за полминуты.

## Уведомления при свёрнутом приложении (Web Push)

Пока CRM открыта — сирена о конце времени работает сама (внутри сайта).
Чтобы сигнал приходил даже когда приложение свёрнуто или закрыто, сервер
отправляет **push** через Google-инфраструктуру — на экране появляется
системное уведомление PlayZone CRM со звуком и вибрацией. APK пересобирать
не нужно: это часть сайта, обновится само.

**Настройка (один раз, всё в браузере):**

1. Залейте свежий код в репозиторий (`git push`) — Vercel обновит сайт сам.
2. Vercel → ваш проект → **Settings → Environment Variables** добавьте три
   переменные (ключи выдаёт разработчик, они уже сгенерированы):

   | Имя | Значение |
   |-----|----------|
   | `VAPID_PUBLIC_KEY` | публичный ключ |
   | `VAPID_PRIVATE_KEY` | приватный ключ |
   | `VAPID_SUBJECT` | `mailto:ваш@почта.kz` |

3. GitHub → **Actions → «Init Neon database» → Run workflow** →
   **seed выключить (снять галочку — важно!)** → Run. Обновится схема:
   добавится таблица подписок и отметка о отправке push. Данные не трогаются.
4. Откройте CRM на телефоне → при первом запуске разрешите уведомления;
   либо меню (иконка палитры в шапке) → **«Уведомления на телефоне» →
   Включить**. Повторите на каждом телефоне сотрудника.
5. На Android разрешите каналы уведомлений: **настройки → Приложения →
   PlayZone CRM → Уведомления: разрешить, звук, вибрация**.

**Чтобы push приходили, даже когда ВСЕ устройства с CRM закрыты** (по
умолчанию доставка срабатывает, пока CRM открыта хоть где-то — например,
на компьютере стойки): откройте `cron-job.org` (бесплатно, без установки),
создайте задачу: URL `https://ваш-адрес/api/push/tick`, интервал —
каждая 1 минута. Всё.

На iPhone push работают с iOS 16.4+ и только у CRM, добавленной на экран
«Домой» (раздел выше) — ограничения Apple.

## Обновления приложения

Данные живут на сайте (сервер + кэш браузера), а не в APK, поэтому обновления
простые:

1. Код обновили на сервере → телефон получает новую версию CRM сам (просто
   закройте и откройте приложение; кэш обновляется автоматически).
2. Поменялась обёртка (адрес, иконка, название) → запустите workflow ещё раз:
   версия (versionCode) вырастет автоматически, APK ставится поверх старого
   **без удаления** — данные клиентов и настройки не теряются.
3. Если первая сборка была давно: скачайте из нового артефакта
   `android.keystore` и загрузите в секрет `ANDROID_KEYSTORE_BASE64`
   (команда `base64 -w 0 android.keystore`) — тогда ключ точно не потеряется,
   даже если кэш GitHub очистится.

## Запасной вариант: PWABuilder (без GitHub)

Откройте `pwabuilder.com`, вставьте HTTPS-адрес CRM → **Package for stores →
Android** → скачайте APK. Результат тот же, но без вашего ключа подписи и без
автоматизации.

## Частые вопросы

**Сменился адрес сайта.** Запустите workflow с новым `pwa_url` и обновите
`assetlinks.json` на сервере. Старый APK продолжит открывать старый адрес,
пока не установите новый.

**Ошибка сборки «Не задан секрет ANDROID_KEYSTORE_PASSWORD».** Выполните
шаг 3.

**Приложение открывается, но с адресной строкой.** Не выполнен шаг 5, либо
Chrome ещё не проверил assetlinks (подождите, перезапустите приложение).

**Бесплатно — это надёжно?** Вариант C (Neon + Vercel) собран и проверен
под лимиты бесплатных тарифов: база не «засыпает», опрос экрана уложен в
1 млн вызовов/мес. Единственный нюанс — Vercel Hobby формально для
некоммерческих проектов; при росте клуба переезд на свой VPS (Вариант A)
занимает ~30 минут, база и данные остаются теми же.

**У сотрудника iPhone — что ему ставить?** Ничего не устанавливайте: APK
на iPhone не ставится и не нужен. Одна и та же ссылка: Safari →
«Поделиться» → «На экран „Домой“» (подробно — раздел выше). Данные общие,
потому что всё живёт на сервере.

**Уведомления не приходят, когда приложение свёрнуто.** Настройте Web Push
по разделу «Уведомления при свёрнутом приложении» — это один раз, всё в
браузере. Также проверьте настройки уведомлений самого приложения (Шаг 6).

**Можно ли в RuStore / APKPure?** Да: RuStore принимает APK без регистрации
юрлица (rustedev.rustore.ru), APKPure — тоже. Google Play — 25 $ один раз,
нужен AAB (можно собрать тем же workflow, добавив задачу `:app:bundleRelease`).
